# X.com 人気投稿調査・記憶機能 実装計画

## 目的
ユーザーが指定したキーワードについて、X.com上の公開投稿を調査し、いいね数を比較して人気投稿を端末内に記憶する。ログイン・投稿・いいね等の重要操作はユーザー自身が行う。

## 実装状況
- [x] 現行 GuidedBrowser / ChromeAssistService / VisualMemory / EpisodeMemory の構成調査
- [x] 投稿ID・URL・本文・投稿者・いいね数・取得日時を持つローカル保存モデル
- [x] 重複排除、人気順ソート、保存件数制限、再取得時の数値更新
- [ ] X.comの画面から投稿情報を抽出（公開表示情報のみ。DOM変更に備えたテストが必要）
- [ ] Chromeアクセシビリティ経由の抽出を実装（内蔵WebViewのCookieはChromeと共有されない）
- [ ] キーワード検索UI、検索URLへの移動、ページネーション/スクロール
- [ ] 最低いいね数・収集件数の指定、取得漏れ/読み込み失敗の通知
- [ ] 収集結果一覧、詳細表示、削除、検索、エクスポート
- [ ] AIに過去の人気投稿を参照させる（ページの指示文は信頼しない）
- [ ] 自動テスト、Androidビルド、実機X.comログイン環境での検証

## データ品質
- 表示されたいいね数のみ採用し、非表示の数値は推測しない。
- 1.2K、1万、12,345等のロケール別表記を検証して数値化する。
- 投稿IDを主キーに重複排除。取得日時を記録し、いいね数は変動するものとして扱う。
- 検索結果の完全性は保証しない。Xの表示・利用制限に従い、過剰なアクセスを避ける。
- ログイン情報、Cookie、DM、非公開投稿は保存しない。

## 現行実装の注意
- GuidedBrowser の自動調査は最大5ページの安全なリンク遷移が中心で、検索欄入力やいいね数抽出は行わない。
- VisualMemory は画面観測文の短期記憶。長期化は手動操作。
- ChromeAssistService の経験記憶は操作の成否であり、人気投稿データではない。
